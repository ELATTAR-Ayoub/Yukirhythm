## Task 1: Defuse the plugin — on Tailwind 3, as a no-op

**Files:** `apps/web/tailwind.config.js`, `apps/web/app/globals.css`

**Why first:** `tailwind.config.js` imports `tailwindcss/lib/util/flattenColorPalette` — a deep internal path **gone in v4**. Its plugin generates the CSS vars `aurora-background.tsx` needs. Removing it *while still on v3* means we can prove the change is visually inert before anything else moves.

**Verified facts:**
- `components/ui/aurora-background.tsx` reads exactly **8** vars: `--white` (L30), `--black` (L31), `--transparent` (L30/31/46), `--blue-500`, `--indigo-300`, `--blue-300`, `--violet-200`, `--blue-400` (all L32).
- Their **exact Tailwind 3 values** (read from `node_modules/tailwindcss/colors`):
  `--blue-300: #93c5fd` · `--blue-400: #60a5fa` · `--blue-500: #3b82f6` · `--indigo-300: #a5b4fc` · `--violet-200: #ddd6fe` · `--white: #fff` · `--black: #000` · `--transparent: transparent`
- **Tailwind 4's default palette moved to oklch**, so v4's `--color-blue-500` is NOT the same colour. **Pinning the v3 hex values is what guarantees the aurora is unchanged** — and it means `aurora-background.tsx` needs no edit at all.

- [ ] **Step 1: Add the pinned palette to `apps/web/app/globals.css`**

Insert into the existing `:root` block (the one starting `--background: 0 0% 100%;`), at the end, just before `--radius`:

```css
    /* Aurora palette — pinned Tailwind 3 values.
       Previously generated by a custom `addVariablesForColors` plugin built on
       tailwindcss/lib/util/flattenColorPalette, a deep internal import removed
       in Tailwind 4. components/ui/aurora-background.tsx reads these by name.
       Pinned rather than mapped to v4's --color-* natives because v4's default
       palette is oklch and would shift these colours. */
    --white: #fff;
    --black: #000;
    --transparent: transparent;
    --blue-300: #93c5fd;
    --blue-400: #60a5fa;
    --blue-500: #3b82f6;
    --indigo-300: #a5b4fc;
    --violet-200: #ddd6fe;
```
These are plain custom properties, NOT theme tokens — do not put them in a Tailwind theme block; nothing should generate utilities from them.

- [ ] **Step 2: Delete the plugin from `apps/web/tailwind.config.js`**

Remove:
1. The `flattenColorPalette` require at the top (lines 1-3).
2. `addVariablesForColors` from the `plugins` array — it becomes `plugins: [require("tailwindcss-animate")]`.
3. The whole `function addVariablesForColors(...)` definition at the bottom.

**Also remove the dead duplicate `popover` key** (line 27, `popover: "#262626"`). It's silently overwritten by the `popover: { DEFAULT: ... }` object below it, so it has **never applied** — removing it changes nothing. Leave the object version alone. (Do NOT "restore" `#262626`; that would be a real visual change.)

Change nothing else in the config.

## Task 3: Port the theme to CSS

**Files:** `apps/web/app/globals.css`, `apps/web/tailwind.config.js`

Port everything from `tailwind.config.js`'s `theme` into CSS. **The token bridge is the critical part.**

- [ ] **Step 1: Directives at the top of `globals.css`**

Replace:
```css
@tailwind base;
@tailwind components;
@tailwind utilities;
```
with:
```css
@import "tailwindcss";
@import "tw-animate-css";

@custom-variant dark (&:is(.dark *));
```
(The old config had `darkMode: ["class","class"]` — a duplicated value; `@custom-variant dark` is the v4 equivalent.)

- [ ] **Step 2: Bridge the shadcn tokens — keep the triplets untouched**

The `:root`/`.dark` blocks define HSL **triplets** (`--background: 0 0% 100%`), consumed as `hsl(var(--background))`. **Do NOT convert them to oklch or change a single value.** Bridge them:

```css
@theme inline {
  --color-background: hsl(var(--background));
  --color-foreground: hsl(var(--foreground));
  --color-card: hsl(var(--card));
  --color-card-foreground: hsl(var(--card-foreground));
  --color-popover: hsl(var(--popover));
  --color-popover-foreground: hsl(var(--popover-foreground));
  --color-primary: hsl(var(--primary));
  --color-primary-foreground: hsl(var(--primary-foreground));
  --color-secondary: hsl(var(--secondary));
  --color-secondary-foreground: hsl(var(--secondary-foreground));
  --color-muted: hsl(var(--muted));
  --color-muted-foreground: hsl(var(--muted-foreground));
  --color-accent: hsl(var(--accent));
  --color-accent-foreground: hsl(var(--accent-foreground));
  --color-destructive: hsl(var(--destructive));
  --color-destructive-foreground: hsl(var(--destructive-foreground));
  --color-border: hsl(var(--border));
  --color-input: hsl(var(--input));
  --color-ring: hsl(var(--ring));
  --color-chart-1: hsl(var(--chart-1));
  --color-chart-2: hsl(var(--chart-2));
  --color-chart-3: hsl(var(--chart-3));
  --color-chart-4: hsl(var(--chart-4));
  --color-chart-5: hsl(var(--chart-5));

  --color-dark-shade-85: #d9d9d9;
}
```
NOTE: `dark-shade-85` was a plain hex in the old config — carry it over. The old config ALSO had a top-level `popover: "#262626"` that Task 1 deleted as dead; do not resurrect it.

- [ ] **Step 3: Port the rest of the theme**

```css

  /* letterSpacing was an OVERRIDE (not extend) in v3 — it replaced Tailwind's
     whole tracking scale. tracking-tight and tracking-widest are used in
     components, so all values are carried over verbatim. */
  --tracking-tightest: -12px;
  --tracking-tighter: -6px;
  --tracking-tight: -0.025em;
  --tracking-normal: 0;
  --tracking-wide: 0.025em;
  --tracking-wider: 0.05em;
  --tracking-widest: 0.25em;

  --font-PIXELADE: "PIXELADE", sans-serif;

  --ease-out-flex: cubic-bezier(0.05, 0.6, 0.4, 0.9);

  --radius-lg: var(--radius);
  --radius-md: calc(var(--radius) - 2px);
  --radius-sm: calc(var(--radius) - 4px);

  --animate-aurora: aurora 60s linear infinite;
}

@keyframes aurora {
  from {
    background-position:
      50% 50%,
      50% 50%;
  }
  to {
    background-position:
      350% 50%,
      350% 50%;
  }
}
```

The proof is that `tracking-tight`, `font-PIXELADE`, `ease-out-flex`, `rounded-lg`, and `animate-aurora` still resolve in the built CSS.
